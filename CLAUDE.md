### Operating rules

1. **Read local before querying remote.** If `REGISTRY.md` can answer "does X exist / what is its ID", trust it instead of calling Pigment. Only query Pigment to fill a gap or verify a suspected staleness.
2. **Registry is updated in the same turn as the change.** Create a list → record its ID before moving on. Delete an object → remove or mark it. The registry must never silently drift from the workspace.
3. **Capture learnings proactively.** When a tool behaves unexpectedly, a formula pattern works (or fails), or a Pigment constraint surfaces, add it to `KNOWLEDGE.md`. Don't wait to be asked.
4. **Keep it clean.** When an experiment is torn down, clean up its registry entries too. Stale IDs are worse than missing ones.
5. **Load the relevant `pigment:*` skill BEFORE designing or planning** (modeling, formulas, boards, views, data imports, performance). These come from the `pigment` plugin — if they're not available, the plugin isn't installed; see README prerequisites.

## Troubleshooting

- `set_metric_input` (or `add_list_items`) returning a generic `"An error occurred invoking '...'"` is almost always an **access rights** issue on that metric/dimension, not a transient MCP failure. Retry once to rule out a true transient, then stop and tell the user to check access rights rather than continuing to retry.
- If reads pass but the first write fails, check Pigment's **Settings → Advanced features → "Enable advanced tools on MCP server"** (per-user, off by default) before anything else.
- When giving example requests, pull real values from the app (`get_list_items`) instead of inventing fictional names.
